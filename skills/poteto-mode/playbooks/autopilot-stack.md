### Autopilot-stack

**You own the stack, never the landing. Build and verify a linear review chain, then hand it to the operator.** Use for "autopilot-stack", "stack them, don't ship", or an equivalent explicit request. Nothing auto-merges.

1. **Load the runtime and hold the boundary.** Resolve delegation, waiting, scheduling, control, and current-task history through **bstack-runtime**. Record the durable objective, repository, branches, and authorized publication operations. Merge and deploy remain forbidden. A request for a plan alone does not start execution.
2. **Give one owner each stack unit.** Each owner gets an isolated branch or worktree, a precise write scope, its intended parent, acceptance checks, and the **poteto-worker** contract. Use [Poteto mode's fresh-worker lifecycle](../SKILL.md#subagents) and the early decision trail, per-unit durable evidence, and child records in [Autopilot-full step 2](autopilot-full.md). Commit and push only within the recorded grant. Owners build, test, exercise the real artifact, triage findings, and run **no-comments**. Report code-ready and each changed-patch SHA before the assigned babysit loop completes. Report STACK-READY only with all required receipts and current-head checks. Apply runtime limits and local fallback without claiming missing independent verification.
3. **Verify every round independently.** Run [Autopilot-full step 4](autopilot-full.md) at code-ready and every changed-patch round. It requires gates, live checks, relevant performance checks, and at least two focused audit lanes with the full brief. Batch every proven issue, including notes, into one fix-forward with tests or repro receipts for every affected site. A fresh owner takes the fix round. Use STACK-READY receipts in place of merge-ready receipts. Nothing enters the chain without a clean verdict. Apply [Shipping's verification reuse rule](shipping.md#verification-reuse) to every verdict and lane considered for reuse.
4. **Keep topology single-writer.** The coordinator alone appends verified units in the operator's order and owns rebases, restacks, and PR base changes. Owners write only their assigned branch and report its tip, base, and intended parent. Use Graphite only when the repository already uses it or the operator requested it. Otherwise build a base-branch chain. Rebase each child onto its parent's exact tip and set its PR base to the parent branch. Only the root PR targets trunk. Force-push only when explicitly authorized, after a current remote-SHA check, with a lease pinned to that SHA. Do not rewrite a shared branch. Owners may fix conflicts in their own scope under the coordinator, but cannot publish topology changes themselves.
5. **Absorb drift and re-verify what moved.** The coordinator rebases the chain from bottom to top when needed. Keep the base stable during fix rounds unless a conflict or trunk-caused CI failure requires movement. Apply [Shipping's verification reuse rule](shipping.md#verification-reuse) after each rewrite. Re-run mergeability and CI at the current head, including when the patch-id is unchanged. Send invalidated lanes through step 3 before delivery. Preserve operator gates and the exact approval boundaries in Autopilot-full step 6.
6. **Audit hourly through the runtime.** Follow [Autopilot-full step 6](autopilot-full.md) for hourly supported-runtime scheduling, durable progress checks, child state, same-route recovery, and changed-only notifications under host policy. Read this playbook and the recorded objective at each audit. Without scheduling, checkpoint locally and report the monitoring gap. Treat expected runtime as evidence, not a kill deadline. Do not leave children running after the queue ends.
7. **Deliver, never land.** Provide one ordered chain of verified PRs or local branches for bottom-up review. The operator lands it. Withhold STACK-READY for gaps or unresolved findings. A hold or stop sends every owner and child a zero-writes instruction immediately and cancels future scheduled work.

**Choosing between the autopilots.** Use Autopilot-full only when independent PRs and explicit merge authority are both present. Use Autopilot-stack when review is retained by the operator or the changes are coupled.

**Reply:** the chain root and tip, one verdict line per unit, trail locations, and anything excluded with the reason.
